# Page override — Dynamic Pricing (`/pricing`)

> Overrides `../MASTER.md` for the Module 28 rules screen. Modelled on `/inventory`: sticky header → stat tiles → one hero visualization → advisory banner → `FilterBar` → card-wrapped `DataTable`.

- **Stat tiles:** 4-up `PricingStatCard` (`features/pricing/PricingStatCard.tsx` — same anatomy as `InventoryStatCard`/`ResourceStatCard`: tone chip + left accent bar + count-up figure + hint, staggered entrance per the CardCount convention). Rules · Live now (pulse dot, toggles the live-only filter) · Deepest discount (toggles `effect=discount`) · Surge windows (toggles `effect=surge`). Figures are derived client-side from the rule list — there is no `/pricing-rules/stats` endpoint.
- **Hero visualization — `PricingWeekGrid`:** 7 day rows × 24h track, each rule a positioned block (success tint = discount, warning tint = surge, dashed muted = paused), 3-hour gridlines, "now" marker on today's row, coverage ratio bar + legend in the header. Blocks are `<button>`s (open the editor) carrying a full `aria-label` and an in-block `−20%` / `+25%` label, so meaning never rests on colour; the table below is the accessible fallback. Horizontal scroll inside the card (`min-w-[680px]`), never on the page body.
- **Clock:** "live now" and the now-marker read **UTC** day/minute-of-day, mirroring `resolvePrice()` in `apps/backend/src/modules/pricing/pricing.service.ts` (schedules are stored as wall-clock strings and compared against UTC, as in `slotEngine`). Do not switch this to `Asia/Vientiane` without changing the engine — the badge would then disagree with the price the customer is quoted.
- **Overlap banner:** warning-tone card (same shape as Inventory's allow-negative-stock banner) when two active rules collide on branch + day + overlapping window + overlapping service scope. Advisory, not an error — it names the rule the engine would pick (cheapest wins; a service-specific rule breaks ties) and offers a "Review overlaps" filter toggle.
- **Filters:** `FilterBar` = search (name/branch/service) + Branch (server-side) + Day + Effect + Status (client-side, so the tiles and grid keep the full branch picture).
- **Table:** Rule (name + live/paused/overlap markers + branch · service) · When (day badge, window, duration, mini 24h position bar) · Effect (net % badge, with the raw `−d% · ×m` factors when both are set) · Price preview (base → final, struck-through base, only for service-scoped rules) · Active (`Switch` + pill) · row actions Edit / Duplicate (creates a paused copy) / Delete. Row click opens the editor.
- **Editor dialog (`PricingRuleDialog`, `max-w-2xl`, scrollable):** three labelled sections — **Scope** (branch, locked on edit · service · name), **Time window** (day chips, multi-select on create = one rule per day, time inputs + duration readout + presets), **Price effect** (discount % and multiplier with preset chips). A tinted **live preview** row shows base → final rounded to 100 LAK via the same formula as the backend, with an editable sample base price when the rule covers all services. Inline `role="alert"` errors per field; an overlap warning renders before save.
- **Copy:** every string under the `pricing.*` i18n namespace (lo + en), including `dowShort.*` for the grid/chips.
